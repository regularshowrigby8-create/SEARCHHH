## How this changed the plan

* Fact 4 being false did **not** change A5: making the release chain tag/dispatch-driven and
  `versionName`-derived is still required to remove the latent fixed-tag collision, and it
  also stops the jobs being dead weight in a sequential PR chain.
* Fact 3's "cannot fail" being false strengthens A4: the lane is not only useless as a gate,
  it injects red noise into PR checks.
* Fact 1's session count being 3 (not 4-7) lowers the expected saving from trigger
  de-duplication alone; the larger single win is removing the JVM re-execution from the
  emulator job (A3).
* No contradiction was found that requires a policy change, so execution continued.
